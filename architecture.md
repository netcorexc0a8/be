# Калькулятор детской смеси: архитектура решения

Дата: 2026-10-02 · Статус: черновик, кода нет

## 1. Цель

Помочь маме за 10 секунд узнать:
- сколько миллилитров готовой смеси нужно ребёнку в сутки;
- сколько миллилитров давать за одно кормление при выбранном числе кормлений;
- (опционально) сколько мерных ложек порошка и воды на одну бутылочку.

Целевая платформа: мобильное приложение или PWA (веб-приложение, которое ставится на телефон как иконка). Основной сценарий: одной рукой, ночью, с ребёнком на руках.

## 2. Методика (доменная модель)

### 2.1 Формула

```
ккал_в_сутки   = норма_ккал_на_кг(возраст) × вес_кг
мл_в_сутки     = ккал_в_сутки / ккал_на_100мл × 100
мл_за_кормление = мл_в_сутки / число_кормлений
```

Норма по возрасту (из методики пользователя):

| Возраст | Норма |
|---|---|
| 0 – 6 мес. | 115 ккал/кг |
| 6 мес. и старше | 110 ккал/кг |

### 2.2 Проверка примера

Вес 5,7 кг, NAN Optipro, 67 ккал:

- 115 × 5,7 = 655,5 ккал
- 655 / 67 = 9,8 → × 100 = **980 мл/сутки** (округление на шагах — часть методики)
- 980 / 6 = **163 мл**, 980 / 7 = **140 мл** за кормление

Результат совпадает. Два уточнения для реализации:

1. **67 ккал указано на 100 мл готовой смеси, а не на 100 г порошка.** На 100 г сухого порошка обычно около 500 ккал. Поэтому формула сразу даёт миллилитры готовой смеси. В интерфейсе и каталоге поле нужно называть однозначно: «ккал на 100 мл готовой смеси», иначе мама может взять цифру «на 100 г» с банки и получить объём в 7 раз меньше.
2. **Округлять по шагам методики пользователя**: ккал целым числом (655), порции до десятых (9,8), сутки = порции × 100 (980 мл), за кормление до целого мл (163, 140). Решение пользователя от 2026-10-02.

### 2.3 Правила как данные, а не код

Нормы (115/110, граница 6 мес.) хранятся в конфигурации `FeedingRules` с версией. Тогда педиатр или сама мама могут их поправить без переписывания логики, а в истории расчётов видно, по какой версии правил считали.

```
FeedingRules {
  version: "2026-10-user-method"
  bands: [
    { fromMonths: 0, toMonths: 6,   kcalPerKg: 115 },
    { fromMonths: 6, toMonths: null, kcalPerKg: 110 }
  ]
  displayDecimals: 0
  feedingsRange: { min: 4, max: 12 }
}
```

## 3. Сущности

| Сущность | Поля | Комментарий |
|---|---|---|
| **Ребёнок** (`Child`) | имя, дата рождения | Возраст считается из даты рождения автоматически, поэтому переход на норму 110 ккал произойдёт сам |
| **Замер веса** (`WeightEntry`) | дата, вес в граммах | История веса; расчёт берёт последний замер. Вес хранить в граммах (целое), вводить можно «5700» или «5,7» |
| **Смесь** (`Formula`) | бренд, название, ступень, ккал/100 мл, граммов в мерной ложке, мл воды на ложку, возраст по ступени | Каталог: преднастроенные + свои |
| **Настройки кормления** (`FeedingPlan`) | ребёнок, смесь, число кормлений (одно значение или диапазон, например 6–7) | У пользователя 6–7 раз, поэтому поддерживаем диапазон и показываем оба результата |
| **Расчёт** (`Calculation`) | дата, входные данные, версия правил, результат | Сохраняется для истории и графика |

## 4. Компоненты

```
┌──────────────────────────── Клиент (PWA / мобильное приложение) ───────────────────────────┐
│                                                                                             │
│  UI-слой                                                                                    │
│   • Экран «Расчёт»: вес, возраст, смесь, число кормлений → крупный результат               │
│   • Профиль ребёнка и история веса                                                          │
│   • Каталог смесей (выбор / добавить свою)                                                  │
│   • История расчётов, график веса и объёма                                                  │
│                                                                                             │
│  Доменное ядро (чистые функции, без UI и сети)                                              │
│   • calculateDailyNeed(weight, ageMonths, formula, rules) → ккал, мл/сутки                 │
│   • splitPerFeeding(dailyMl, feedings) → мл за кормление (для каждого значения диапазона)  │
│   • toScoops(ml, formula) → ложки порошка + вода (если в каталоге есть данные о ложке)     │
│   • validate(input) → ошибки и предупреждения (см. раздел 5)                                │
│                                                                                             │
│  Хранилище на устройстве (IndexedDB / SQLite)                                               │
│   • дети, вес, план, история, свои смеси, кэш каталога                                      │
│                                                                                             │
└───────────────────────────────▲─────────────────────────────────────────────────────────────┘
                                │ (опционально, при наличии сети)
                    ┌───────────┴────────────┐
                    │  Сервер каталога        │  статический JSON: смеси + FeedingRules
                    │  (CDN / статик-хостинг) │  с версией; без персональных данных
                    └────────────────────────┘
```

Ключевые решения:

- **Offline-first, всё считается на устройстве.** Формула простая, сервер для расчёта не нужен. Приложение работает ночью без интернета.
- **Доменное ядро отдельно от UI.** Его легко покрыть тестами (пример 5,7 кг → 980 мл — первый тест) и переиспользовать, если позже появится телеграм-бот или веб-версия.
- **Персональные данные о ребёнке не покидают телефон** по умолчанию. Это снимает большую часть вопросов приватности. Синхронизация между телефонами двух родителей — отдельный этап (раздел 8).
- **Сервер только раздаёт каталог смесей и правила** статическим файлом. Новые смеси добавляются без обновления приложения.

## 5. Валидация и безопасность

Калькулятор даёт рекомендации по питанию младенца, поэтому это главный риск продукта.

**Жёсткие ошибки (расчёт не показываем):**
- вес вне правдоподобного диапазона (например, меньше 1,5 кг или больше 20 кг);
- ккал/100 мл вне диапазона, типичного для готовой смеси (примерно 60–80); значение около 500 почти наверняка «на 100 г порошка», подсказываем это;
- число кормлений вне 4–12.

**Предупреждения (показываем расчёт с плашкой):**
- дата последнего взвешивания старше 2–3 недель: «вес мог измениться, взвесьте ребёнка»;
- возраст 6+ мес.: после введения прикорма объём смеси обычно снижается, расчёт показывает потребность без учёта прикорма;
- суточный объём выше порога, который задаёт педиатр (верхняя граница хранится в `FeedingRules`, а не захардкожена);
- недоношенный ребёнок или особые смеси (гипоаллергенные, лечебные): методика может не подходить.

**Обязательно:**
- постоянная пометка «Расчёт ориентировочный, согласуйте с педиатром» и показ формулы, по которой считали (прозрачность вычислений);
- нормы 115/110 ккал/кг и пороги перед публикацией проверить у педиатра; в коде они только данные из конфигурации.

## 6. Пользовательский сценарий

1. Первый запуск: имя, дата рождения, текущий вес, выбор смеси из каталога, число кормлений (например 6–7).
2. Главный экран сразу показывает результат крупно:
   > **980 мл в сутки**
   > 6 кормлений: **163 мл** · 7 кормлений: **140 мл**
   > (≈ N ложек + M мл воды, если данные о ложке есть)
3. После взвешивания: «Новый вес» → результат обновляется, старый сохраняется в историю.
4. Ребёнку исполнилось 6 мес.: приложение само переходит на 110 ккал/кг и сообщает об этом.

## 7. Технологический выбор (рекомендация)

| Слой | Вариант | Почему |
|---|---|---|
| Клиент | PWA на React/Vue или Flutter | PWA быстрее всего запустить и не требует магазинов приложений; Flutter, если нужны нативные уведомления и сторы |
| Хранилище | IndexedDB (PWA) / SQLite (Flutter) | Офлайн, данные на устройстве |
| Каталог | JSON-файл на статическом хостинге | Ноль серверного кода |
| Тесты ядра | Таблица эталонных примеров | Пример из методики, граница 6 мес., диапазон кормлений, ошибки ввода |

Для MVP хватит PWA без бэкенда.

## 8. Этапы

1. **MVP:** один ребёнок, ручной ввод ккал или выбор смеси из небольшого каталога, расчёт суток и порции, валидация, предупреждение о педиатре.
2. **Удобство:** история веса и график, перевод в мерные ложки, автопереход на норму 6+ мес.
3. **Семья:** несколько детей, синхронизация между телефонами родителей (тогда понадобится бэкенд с авторизацией и шифрованием).
4. **Дальше по желанию:** напоминания о кормлении, дневник фактически съеденного объёма, экспорт для педиатра (PDF).

## 9. Решение: приложение для себя (2026-10-02)

Это упрощает архитектуру:
- **Без сервера вообще.** Каталог смесей не нужен: одна-две свои смеси вводятся вручную (NAN Optipro, 67 ккал/100 мл). Раздел «Сервер каталога» из схемы убирается.
- **PWA на одном статическом хостинге** (например GitHub Pages) или даже один HTML-файл, сохранённый на домашний экран телефона.
- **Приватность и юридический дисклеймер упрощаются**: данные только на вашем телефоне. Пометка о педиатре остаётся как напоминание себе.
- **Валидация остаётся** (опечатка в весе ночью всё равно возможна), но в облегчённом виде.
- Этап 3 «Семья» нужен, только если второй родитель тоже будет пользоваться; тогда проще всего экспорт/импорт файла, а не бэкенд.

## 10. Число кормлений (решение 2026-10-02)

Задаётся вручную, рядом подсказка по возрасту из `FeedingRules.feedByAge` (0–1 мес. 7–8, 1–6 мес. 6–7, 6–9 мес. 5–6, 9+ мес. 4–5). Подсказка применяется только по кнопке.

## 11. Открытые вопросы

- Нужно ли учитывать прикорм после 6 месяцев (уменьшать объём смеси)?
- Нормы и пороги проверить у педиатра.
